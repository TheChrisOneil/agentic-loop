Workshop Compiler: use case to design to stub loop

repo thechrisoneil/agentic-loop path course/workshop/ branch claude/sharp-darwin-7innrk @ 08718be 2026-09-24

Purpose Specify the workshop tooling that compiles a process description into a validated design and, on named acceptance, scaffolds a stub loop.

EX The tooling is a five-state job pipeline with one model call (generate.sh). Validation, rendering, acceptance and scaffolding are deterministic bash and awk. make test passes 11 of 11 after the mktemp fix in commit cb64ed8.

LogicalClasses and patterns; end user functionality DevelopmentPackages and files; the programmer's view +1 ScenariosUse case to running stub loop ProcessStates, control flow, repair loop PhysicalWorkstation, CLI, model endpoint

1. Description

The tooling behaves as a compiler. The source is prose, the intermediate representation is a .design file, and the target is a runnable loop.

use-case.txt→ screen.awk rule→ generate model→ validate V1–V22 gate→ brief + render→ accept sha256 gate→ scaffold→ loops/<slug>/

Every job state transition is appended to jobs/<slug>/job.tsv (start.sh:8-9).

ArtifactRoleEvidence
jobs/<slug>/use-case.txtSource; the process in the owner's wordsgenerate.sh:45-59
method/GENERATE.md, schema/DESIGN-FORMAT.mdWritten method and target grammar the model fillsgenerate.sh:94-97
jobs/<slug>/proposed.designIntermediate representation: @meta @assumptions @unit @steps @gates …DESIGN-FORMAT.md
memory/acceptances.tsvAppend only, hash chained approval registeraccept.sh:1-16
memory/usage.tsvCost ledger; nre for design, run per unitlog-cost.sh:7-14
loops/<slug>/Target; a stub loop with TODO: steps that ticks immediatelyscaffold.sh:1-10

3. Process view

The job lifecycle is a state machine persisted as one file per job. A job resumes where it stopped.

stateDiagram-v2
  [*] --> intake: make start
  intake --> intake: screen or generate refused
  intake --> designed: validated design + brief
  designed --> discussing: d, revise (max 3)
  discussing --> designed: re-validated
  designed --> designed: s, stop
  designed --> accepted: a, typed phrase + name
  accepted --> accepted: scaffold refused
  accepted --> built: scaffold ok, make tick
  built --> [*]

Evidence: set_state calls in start.sh, lines 51-190.

Generate activity with bounded repair

flowchart TD
  U[use-case.txt] --> S{screen.awk}
  S -->|TOO_LONG, TOO_SHORT, INJECTION| R1([REFUSED + next human action])
  S -->|OK| P[build_prompt: GENERATE.md + DATA + author, date]
  P --> M[[claude -p, JSON]]
  M --> C[log-cost.sh nre]
  C --> X[extract from first @meta]
  X --> V{validate.sh}
  V -->|pass| B[brief.sh: BRIEF.md, sequence.mmd, flow.mmd, svg]
  V -->|fail, attempts left| F[findings.txt fed back]
  F --> P
  V -->|fail, 3 attempts spent| R2([REFUSED; draft kept])

REPAIRS=2 gives at most three model attempts (generate.sh:117-160).

5. Physical view

7. Findings

fixed GNU mktemp defect in tests. mktemp -t name is BSD syntax. On GNU it returned an empty path, so ACCEPT_REGISTER and USAGE_LEDGER fell back to the real memory/*.tsv, and the tests appended rows to the audit register. flow.sh reported a false failure.

Fix: explicit ${TMPDIR:-/tmp}/name.XXXXXX template, abort on empty path, cat fallback for column. Commits cb64ed8 (workshop tests) and 08718be (course/check.sh). Result: 11 PASS, 0 FAIL; memory/ unchanged.

HIPAA PHI egress in generation. Inference. examples/prior-auth.use-case.txt describes a PHI workflow. generate.sh sends the use case text to the model endpoint. Real clinical descriptions require a BAA covered endpoint and de-identified wording. The same applies to JUDGE_MODE=claude in scaffolded loops.

scope Stub output. The scaffold builds the loop's shape only. Step logic remains TODO: placeholders, listed by make todo inside the loop.
